# Кафе «Виктория» — сайт с доставкой

Next.js (App Router) + TypeScript + Tailwind CSS.

## Запуск

```bash
npm install
npm run dev
```

Сайт будет доступен на http://localhost:3000

## Структура проекта

```
src/
  app/
    layout.tsx      # корневой layout: шрифты, глобальные стили
    (site)/         # публичный сайт (route group, свой layout с Header/Footer/CartProvider)
      page.tsx      # главная страница с меню
      cart/         # страница корзины
      checkout/     # оформление заказа (форма контактов, адреса, способ оплаты)
      order/[id]/   # подтверждение заказа со статусом
    admin/          # админка (защищена proxy.ts)
      login/        # вход по паролю
      orders/       # список заказов, смена статуса
      menu/         # добавление/редактирование/удаление блюд
    api/orders/            # приём заказов (POST), создание платежа в ЮKassa
    api/yookassa/webhook/  # приём уведомлений об оплате от ЮKassa
    api/admin/             # login/logout, CRUD для заказов и меню (только для админки)
  proxy.ts          # защита /admin и /api/admin — редирект на логин без сессии
  components/       # переиспользуемые UI-компоненты (включая components/admin/)
  context/          # CartContext — состояние корзины (localStorage)
  data/             # categories (статично) + доступ к меню через lib/menu-store
  types/            # типы TypeScript
  lib/              # yookassa.ts, telegram.ts, orders.ts, menu-store.ts, adminAuth.ts
```

## Готово на этом этапе

- Каркас Next.js проекта, Tailwind, шрифты
- Главная страница с каталогом блюд по категориям
- Корзина с состоянием (добавление/удаление, изменение количества, localStorage)
- Оформление заказа: форма контактов и адреса, выбор способа оплаты
- Онлайн-оплата через ЮKassa: `/api/orders` создаёт платёж и возвращает ссылку на оплату, `/api/yookassa/webhook` подтверждает оплату по уведомлению (перепроверяя статус через API ЮKassa, а не доверяя телу вебхука)
- Уведомления о заказах в Telegram: при заказе с оплатой курьеру — сразу, при оплате картой — после подтверждения оплаты вебхуком
- Админка на `/admin` (защищена паролем): список заказов со сменой статуса, добавление/редактирование/удаление блюд меню

### Как войти в админку

Впишите `ADMIN_PASSWORD` в `.env` (см. `.env.example`) и откройте `/admin` — редирект приведёт на `/admin/login`. Это простая парольная защита без учёток и ролей: одна сессия на весь сайт, без разграничения прав между сотрудниками. Для нескольких сотрудников с разными правами понадобится что-то более серьёзное (например, NextAuth).

### Как включить оплату

Впишите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в `.env` (см. `.env.example`) — их выдают в личном кабинете ЮKassa. Без ключей выбор «Онлайн картой» в чекауте вернёт понятную ошибку, а «Курьеру при получении» работает и без них.

В личном кабинете ЮKassa нужно указать URL для уведомлений: `https://<ваш-домен>/api/yookassa/webhook`.

### Как включить Telegram-уведомления

1. Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot` — получите `TELEGRAM_BOT_TOKEN`.
2. Узнайте `chat_id`: напишите боту любое сообщение, затем откройте `https://api.telegram.org/bot<TOKEN>/getUpdates` в браузере и найдите `"chat":{"id": ...}` в ответе. Для уведомлений в группу — добавьте бота в группу и используйте её `chat_id` (обычно отрицательное число).
3. Впишите оба значения в `.env` (см. `.env.example`).

Без настройки уведомления просто не отправляются — в логе сервера появится предупреждение, заказ при этом оформляется как обычно.

## Приватность и доступ

### Репозиторий на GitHub

Приватный — виден только владельцу аккаунта и тем, кого вы явно добавите. Дать доступ другому человеку: на странице репозитория → Settings → Collaborators and teams → Add people.

### Персональные данные клиентов

Заказы (`.data/orders.json`) содержат имя, телефон, адрес и комментарий каждого клиента. Файл лежит только на сервере и не попадает в git (см. `.gitignore`), но сам по себе не зашифрован — при выборе хостинга и резервного копирования учитывайте, что там персональные данные, и ограничивайте доступ к серверу.

### Секреты (`.env`)

`.env` не коммитится (в `.gitignore`) — `ADMIN_PASSWORD`, `YOOKASSA_SECRET_KEY`, `TELEGRAM_BOT_TOKEN` храните только там. Передавайте их команде не через git и не в чатах, а через отдельный защищённый канал (секреты хостинга, менеджер паролей и т.п.).

### Доступ к админке

`/admin` защищён одним общим паролем без учёток и ролей — у кого есть пароль, тот может менять и заказы, и меню всего сайта. Перед тем как открывать сайт на публичном домене, обязательно смените тестовый пароль на свой и сообщайте его только тем, кому он действительно нужен.

## Известные ограничения

- Заказы (`.data/orders.json`) и меню (`.data/menu.json`) хранятся в файлах на сервере (не в git) — временное решение вместо БД. Пробовали in-memory `Map` — в Next.js (Turbopack) route handler и RSC-страница получают разные инстансы модуля, поэтому состояние не шарилось; файловое хранилище лишено этой проблемы. На проде, особенно при serverless-хостинге без постоянного диска, нужна настоящая БД.
- Админка — однопользовательская, без ролей и логов действий.
